The problem

Teaching online needs more than a text box

01

Lessons mix formats

A good explainer moves between prose, math, diagrams, code and live demos. Most blog editors handle one of them well.

02

AI help means sending drafts away

Writing assistants usually run on a paid, hosted model, so unpublished work leaves the writer's machine.

03

Learning gets buried

Readers sift through news and feeds to find pieces that actually teach something they can keep.

The solution

One place to write, co-write and learn

Five post formats

Rich Text, Markdown, LaTeX, HTML/CSS/JS with live preview, and Product Launch. KaTeX math and Mermaid diagrams render in every format.

A co-writer on open models

A streaming Copilot beside the editor. Local Ollama by default, or any OpenAI-compatible endpoint you choose.

Reading that teaches

A personalised feed, Pulse (educational RSS), Research (arXiv summaries) and Learn (paths built from existing posts).

Assistants can help

A remote MCP connector with OAuth, plus a local stdio MCP server, so AI assistants can read and write the blog.

How it works

One Next.js server, one MongoDB database

Publishing a post: cookie checked in proxy.js, session version checked in the handler, post saved to MongoDB.

Automation

AI posts stay drafts until they pass a fact-check

  • fetch-newsevery 4 h21 RSS feeds, kept only if the model judges them educational
  • fetch-researchevery 6 hrecent arXiv papers, summarised in plain language
  • generate-topics00:00 UTCa batch of new topic ideas
  • generate-posts06:00, 18:00posts and labelled startup concepts
  • generate-seriesSun 03:00learning paths that order existing posts

Admins can pause everything, switch each job off, run it now and read every run's log.
